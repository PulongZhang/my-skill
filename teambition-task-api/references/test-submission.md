# Teambition 测试单与提测

本参考适用于用户明确要求在 TB 提测或提交测试、指定测试人及可确定的项目和内容。提测不是工时登记，也不是把任务标记完成；用户已明确授权创建、指派和提测时，不重复要求其提供系统内部状态 ID。查询可以直接执行，缺少必要的项目、测试人、目标任务或写入授权时先澄清。

以下页面字段、任务类型和状态在 **S1867 内网部署**于 2026-11-12 实际核对；其他项目或部署应按实时配置验证，不能照搬 ID、字段和状态名称。通用请求与状态校验见 [API 参考](api.md#查询项目任务类型与工作流状态)，S1867 的已知映射见 [项目参考](s1867.md)。

## 定位和防重

1. 用项目参考、用户链接或当前已登录页面确定同源 origin、项目和测试人，校验人员 ID、名称及项目成员身份。明确区分“测试单”和“测试任务”：S1867 两者是不同 SFC，提测单通常使用“测试单”，实际以本次项目配置和用户要求为准。
2. 若用户指定任务 ID，先通过任务详情、`tasks/bulk` 和 GraphQL 核对标题、项目、SFC、执行者、状态以及未删除、未归档、未完成；不能用标题相似替代准确目标。没有 ID 时对目标执行者执行组织级未完成任务 GraphQL 全分页，再按项目、任务类型和准确标题在本地匹配。
3. 执行者全分页只能证明该执行者的候选范围，不能据此宣称全项目没有同名任务。需要覆盖其他执行者、已完成或归档任务时，使用已验证且完整分页的相应查询；无法证明范围完整、游标无进展、存在同名不同类型或多个候选时停止消歧，不以未命中推断不存在。已唯一匹配的目标只在用户授权范围内处理。
4. 创建前一次性核对项目任务列表、阶段、SFC、工作流和实际状态。阶段由任务列表接口确定；起始状态、已提测状态分别从 SFC 的 `taskflowstatuses` 核对所属工作流、有效 ID、未归档与 `kind`。创建只用唯一 `kind=start`；S1867 的“已提测”是 `kind=unset` 中间状态。配置缺失、不唯一或不匹配时停止，不猜测。

## 填写与创建

只根据可核实的信息填写标题、测试人、测试内容、影响范围、验证步骤和版本。镜像或构建信息应能关联本次实际构建；构建成功、推送日志、独立仓库核验及业务联调的证据分别说明，不能把其中一项夸成其他项。历史测试注明执行时间，未验证的测试、演示、环境、时间和截止日期不编造。

S1867“测试单”页面包含必填的“前端服务&版本号”“后端服务&版本号”和“备注”。前端确无改动时，可据事实填写沿用现有环境版本；备注应覆盖提测内容、回归范围、兼容性和已知限制。不要复制其他提测单的业务数据，也不要保留与本次事实不符的默认 Y/N 内容。

用户明确要求新建且防重和配置检查通过后，按已授权项目创建一次，初始状态为已核验的 `kind=start`，执行者为目标测试人。S1867 通过页面创建并填写上述字段已实际验证；富文本和自定义字段的独立写 API 契约尚未验证，不得从普通任务或工时模板猜测 JSON。需要这些字段时可使用已登录 Chrome 的现有创建页面，并在写后独立核对。

创建后读取服务返回的任务 ID，再用任务详情、`tasks/bulk` 和 GraphQL 核对标题、项目、列表、阶段、SFC、执行者、初始状态、未删除、未归档、未完成及所填版本与备注。`tasks/bulk` 不提供归档布尔值，必须由 GraphQL 核对。读取自定义字段时只返回所需的文本值，不输出富文本的签名 URL 或原始对象。

## 提交与回查

用户要求提测时，只有创建或复用目标已独立核验、必填内容齐全且当前状态允许提交，才使用实际 SFC 和工作流中的“已提测”状态。发出 PUT 前再次读取任务身份、执行者、删除/归档/完成标志、当前状态和该 SFC 的实时目标状态；与已核验方案不符或发生并发变化时停止。工作流状态更新只能使用 `PUT /api/tasks/{id}/taskflowstatus`，传实际 `_scenariofieldconfigId` 和目标 `_taskflowstatusId`，保持 `sfcRequiredValidateEnable: true`；不得默认跳过必填校验。状态配置、请求体及终态区别见 [API 参考](api.md#更新工作流状态)。

写后以任务详情和 `tasks/bulk` 独立核对任务 ID、项目、SFC、执行者、目标状态和 `isDone=false`，并通过 GraphQL 核对未归档、未删除。仅 HTTP 成功不能证明提测成功。已有状态正是目标且内容、身份一致时跳过重复转换；若已完成、已归档、发生并发修改、状态或内容不符，停止并报告。

创建和状态转换没有可证明的幂等键。创建响应丢失或页面未关闭时，先按已知 ID 或完整候选范围查询；已创建则保留该 ID 继续核对，不重建。转换响应丢失时先读取当前状态；确已生效则不重发，确实失败且仍满足授权与校验后才可处理，无法判定则报告未知。创建成功但提测失败时，报告已有任务及其状态，不能说已提测。

手动 F12 脚本仍遵循主技能的“运行时查询 → 校验 → 预览 → `window.confirm` → 写入 → 独立验证”；已登录 Chrome 的执行不重复要求用户确认已经明确授权的同一业务范围。

## 直达链接和输出

S1867 的任务详情已验证可用同源 `https://tb.cet-electric.com:4753/task/{taskId}` 在新标签直接打开。使用本次独立查得的 24 位十六进制任务 ID，结合已确认 origin 生成 Markdown 直达链接，并验证页面确实显示同一任务。该部署的项目内 `/project/.../tasks/scrum/.../task/{taskId}` 复制链接曾在新标签跳回已关闭的分组，不要将它当作已验证直达链接。

其他部署先验证直达地址和登录态；无法验证时如实说明，不凭经验声称链接可用。不要将 token、签名查询参数、Cookie、原始富文本对象或无关项目元数据写入输出。最终报告任务标题、项目、测试人、实际状态、直达链接、版本及任何尚未验证的环节。

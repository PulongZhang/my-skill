# Agent Note: 同步 Teambition 原文件版本 API

Status: implemented

## Problem

`flow-engine` 已将 TB 文件交付改为复用 Chrome 登录态调用 AWOS 和原文件版本接口，通用 `teambition-task-api` 仍只记录任务与工时。用户要求将这条接口同步到本技能仓库，避免后续重新依赖页面上传控件或重复探查。

## Decision

在 `teambition-task-api` 增加按需读取的文件版本参考，记录文件定位、上传 token、页面 S3 SDK、原文件版本提交及独立下载核验。主技能增加能力入口和标准流程，API 索引链接到新参考；浏览器定位优先复用当前聊天已确认的同源页面，省去重复列页与切换。

同步的是接口契约与执行规则，不复制项目专属的 SQL 路径白名单、文件夹映射或持续上传授权。通用操作必须有明确来源文件、部署、项目、目录及原文件目标；已有会话授权继续有效。只维护技能不实际上传，也不更新其他安装副本或推送远端。

来源为 `D:/CETWorkSpace/flow-engine` 提交 `99d1bf74` 的 `publish_bpm_sql.mjs` 和 API 决策笔记。其接口依据是 2026-11-03 S1867 部署前端的只读检查，15 项离线测试属于来源实现的历史证据，不称为本仓库已完成真实上传验证。

## Alternatives considered

复制完整 BPM 上传器可以直接执行，但会将固定项目、SQL 文件名及目录授权带入通用 TB 技能，并形成双份实现，因此只同步自包含的接口参考与规则，BPM 场景继续使用其项目 helper。

只在原 API 文档追加两个 POST 路径最简短，但无法表达对象上传、版本关联和独立核验的区别，也容易误重试。因此用独立参考承载完整契约，主技能只保留流程入口。

## Verification

- 对照来源实现核对请求字段、原 ID、SDK 模块与参数、凭证边界、并发检查、无自动重试和独立下载核验；新参考明确来源部署及离线验证限制。
- 通过 `uv run` 执行系统 skill-creator 的 `quick_validate.py`；15 个本地 Markdown 引用和 2 个 JSON 示例检查通过。仓库未配置根 npm 脚本，直接用 Node.js 执行现有笔记 tree、format、archived 三项校验，6 篇笔记及零条归档全部通过；`git diff --check` 通过。
- 本次仅维护技能和接口参考，没有新增上传器或执行真实上传，也不重复运行来源项目的离线测试。

## Consequences

通用技能可以直接发现文件版本 API，避免重复依赖页面控件；代价是接口与 S3 模块编号来自当前内网部署，升级或其他部署必须先核对，不能宣称通用稳定契约。文件上传成功不等于原文件版本更新成功；结果未知时只读核查，不能整体重发。项目专属 helper 继续由项目维护，本仓库的接口参考需要随部署契约变化同步。
